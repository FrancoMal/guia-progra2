Conjunto (Set)

1. ¿Qué es y cuándo se usa?

Un conjunto es una colección de elementos con dos reglas clave: no hay repetidos (cada elemento aparece a lo sumo una vez) y no hay orden (no existe "el primero" ni "el último"). Es la misma idea que el conjunto matemático: lo único que importa es si un elemento pertenece o no.

Se usa cuando querés modelar pertenencia sin que importe la posición ni la cantidad de veces: marcar nodos ya visitados en un grafo, llevar la lista de elementos únicos de una colección, o representar relaciones (un diccionario que asocia una clave a un conjunto de valores).

{ 7, 3, 5 }≡ { 5, 7, 3 }

Los dos conjuntos del diagrama son iguales: como no hay orden, da lo mismo en qué secuencia estén los elementos.

2. Interfaz del TDA

Las operaciones del TDA Conjunto y sus precondiciones:

public interface ConjuntoTDA {
    void inicializarConjunto();   // Sin precondiciones.
    void agregar(int x);          // Conjunto inicializado.
    void sacar(int x);            // Conjunto inicializado.
    int elegir();                 // Conjunto inicializado y no vacío.
    boolean pertenece(int x);     // Conjunto inicializado.
    boolean conjuntoVacío();      // Conjunto inicializado.
}

El Set de Monzón es minimalista: no tiene pertenece (ni un contains), y choose() es aleatorio igual que elegir(). Para saber si un elemento está, hay que recorrer con choose/remove sobre una copia del conjunto y fijarse si aparece.

💡 Sobre elegir() Como no hay orden, no tiene sentido pedir "el primero". elegir() devuelve algún elemento cualquiera del conjunto, y no es determinista: dos llamadas seguidas sobre el mismo conjunto pueden devolver elementos distintos. Pensalo como un bolillero: metés la mano y sacás una bolilla al azar. Eso sí, elegir() mira pero no saca: el elemento sigue adentro del conjunto (para quitarlo hay que llamar sacar(x)). Su única precondición es que el conjunto no esté vacío. Por eso nunca escribas código que dependa de que elegir() devuelva "el primero", "el último" o un valor fijo: no hay garantía de cuál te toca.

3. Implementaciones

En ambas implementaciones la clave es la misma: para no tener repetidos, antes de agregar se chequea pertenece. Si el elemento ya está, no se hace nada. Por eso agregar, sacar y pertenece necesitan recorrer la estructura buscando el elemento.

Con lista dinámica (LD)

Cada elemento es un nodo de una lista enlazada simple. Como el orden no importa, se agrega siempre adelante (en origen). pertenece recorre la lista buscando el valor, y sacar reengancha los nodos para saltearse el que se quita.

public class ConjuntoLD implements ConjuntoTDA {
    class Nodo { int valor; Nodo sig; }   // Cada nodo guarda un valor y apunta al siguiente.
    Nodo origen;                          // Referencia al primer nodo de la lista.

    public void inicializarConjunto() { origen = null; }   // Conjunto vacío = lista vacía.

    public void agregar(int x) {
        if (!this.pertenece(x)) {   // Sólo se agrega si NO está ya en el conjunto.
            Nodo nuevo = new Nodo();
            nuevo.valor = x;
            nuevo.sig = origen;     // El nuevo apunta al viejo origen...
            origen = nuevo;         // ...y pasa a ser el nuevo origen.
        }
    }

    public void sacar(int x) {
        if (origen != null) {
            if (origen.valor == x) {            // Caso 1: el elemento está en el primer nodo.
                origen = origen.sig;
            } else {                            // Caso 2: lo busco con un "turista".
                Nodo turista = origen;
                while (turista.sig != null && turista.sig.valor != x)
                    turista = turista.sig;
                if (turista.sig != null)        // Si lo encontré, lo salteo.
                    turista.sig = turista.sig.sig;
            }
        }
    }

    public int elegir() {                           // Devuelve algún elemento, elegido al azar. No lo saca.
        int paso = (int) (Math.random() * this.contar());   // ¿Cuántos nodos avanzo? Un número al azar.
        Nodo turista = origen;
        for (int i = 0; i < paso; i++)               // Avanzo "paso" nodos desde el origen.
            turista = turista.sig;
        return turista.valor;                        // Devuelvo el valor del nodo donde caí.
    }

    private int contar() {                           // Cuántos elementos hay (auxiliar para elegir al azar).
        int n = 0;
        Nodo turista = origen;
        while (turista != null) { n++; turista = turista.sig; }
        return n;
    }

    public boolean pertenece(int x) {
        Nodo turista = origen;
        while (turista != null && turista.valor != x)   // Recorre buscando x.
            turista = turista.sig;
        return (turista != null);                       // true si lo encontró.
    }

    public boolean conjuntoVacío() { return (origen == null); }
}

Con arreglo (AR)

Los elementos se guardan en un arreglo y un entero cant indica cuántos hay (y, por lo tanto, la próxima posición libre). Como el orden es irrelevante, agregar pone el elemento al final. El truco está en sacar: en vez de mover todo, se reemplaza el elemento por el último y se decrementa cant.

public class ConjuntoAR implements ConjuntoTDA {
    int[] arr;   // Acá se guardan los números del conjunto. El orden es irrelevante.
    int cant;    // Cantidad de elementos. Apunta a la primera posición libre de "arr".

    public void inicializarConjunto() {
        arr = new int[20];   // Tamaño máximo del conjunto.
        cant = 0;            // Inicialmente no hay elementos.
    }

    public void agregar(int x) {
        if (!this.pertenece(x)) {   // Sólo se agrega si NO está ya en el arreglo.
            arr[cant] = x;
            cant++;
        }
    }

    public void sacar(int x) {
        int i = buscar(x);
        if (i != -1) {
            arr[i] = arr[cant - 1];   // Se sobreescribe con el último elemento...
            cant--;                   // ...y se decrementa "cant".
        }
    }

    public int elegir() {                   // Devuelve algún elemento, elegido al azar. No lo saca.
        double num = Math.random() * cant;
        int inx = (int) Math.floor(num);
        return arr[inx];
    }

    public boolean pertenece(int x) {
        int i = buscar(x);
        return (i != -1);   // Si es -1 no se lo encontró; en caso contrario, sí.
    }

    public boolean conjuntoVacío() { return (cant == 0); }

    private int buscar(int x) {   // Recorre el arreglo y devuelve la posición de x, o -1 si no está.
        int i = cant - 1;
        while (i >= 0 && arr[i] != x)
            i--;
        return i;
    }
}
💡 Cómo se evita el duplicado En las dos implementaciones, agregar(x) empieza con if (!pertenece(x)). Esa verificación es lo único que garantiza la regla "sin repetidos" del conjunto. Si la sacaras, el TDA dejaría de ser un conjunto.

Recorrer un conjunto (patrón destructivo)

El TDA Conjunto no tiene iterador: no hay un for que recorra los elementos uno por uno como en una lista. Lo único que tenés para "sacar" elementos es elegir() (que devuelve uno cualquiera) y sacar(x) (que lo quita). Por eso, para recorrer todo el conjunto, el patrón es vaciarlo: elegís un elemento, lo usás y lo sacás, hasta que quede vacío.

while (!c.conjuntoVacío()) {   // Mientras queden elementos...
    int x = c.elegir();        // ...elijo uno cualquiera...
    // ...acá uso x (imprimirlo, sumarlo, lo que sea)...
    c.sacar(x);                // ...y lo saco, para no volver a tomarlo.
}
// Al terminar, c quedó VACÍO.
⚠️ Este patrón destruye el conjunto Al terminar el while, el conjunto quedó vacío: lo recorriste sacándole todo. Si no querés destruir el conjunto que recibiste (porque lo vas a seguir usando), trabajá sobre una copia y recorré la copia. Lo mismo aplica a lo que devuelven operaciones como claves() de un diccionario o vertices() de un grafo: te entregan un conjunto, y si lo recorrés con este patrón lo vaciás. Si lo necesitás de nuevo, copialo antes.

Operaciones entre conjuntos

Las operaciones clásicas unión, intersección y diferencia no son parte del TDA: se programan por fuera, usando solo las operaciones públicas (elegir, sacar, pertenece, agregar, conjuntoVacío). La técnica es siempre la misma: recorrer una copia de cada conjunto con el patrón destructivo, para no romper los originales.

// A ∪ B: todos los elementos que están en A o en B (sin repetidos).
public ConjuntoTDA union(ConjuntoTDA a, ConjuntoTDA b) {
    ConjuntoTDA r = new ConjuntoLD();
    r.inicializarConjunto();              // Arranco del VACÍO (neutro de la unión).
    ConjuntoTDA ca = copia(a);            // Trabajo sobre copias para no destruir A ni B.
    while (!ca.conjuntoVacío()) { int x = ca.elegir(); r.agregar(x); ca.sacar(x); }
    ConjuntoTDA cb = copia(b);
    while (!cb.conjuntoVacío()) { int x = cb.elegir(); r.agregar(x); cb.sacar(x); }
    return r;   // agregar() ya evita los repetidos: lo que está en ambos entra una sola vez.
}

// A ∩ B: los elementos que están en A Y en B.
public ConjuntoTDA interseccion(ConjuntoTDA a, ConjuntoTDA b) {
    ConjuntoTDA r = new ConjuntoLD();
    r.inicializarConjunto();
    ConjuntoTDA ca = copia(a);            // NO arranco del vacío "puro": recorro A.
    while (!ca.conjuntoVacío()) {
        int x = ca.elegir();
        if (b.pertenece(x)) r.agregar(x); // Lo guardo solo si TAMBIÉN está en B.
        ca.sacar(x);
    }
    return r;
}

// A − B: los elementos de A que NO están en B.
public ConjuntoTDA diferencia(ConjuntoTDA a, ConjuntoTDA b) {
    ConjuntoTDA r = new ConjuntoLD();
    r.inicializarConjunto();
    ConjuntoTDA ca = copia(a);            // Recorro A (no el vacío).
    while (!ca.conjuntoVacío()) {
        int x = ca.elegir();
        if (!b.pertenece(x)) r.agregar(x); // Lo guardo solo si NO está en B.
        ca.sacar(x);
    }
    return r;
}
💡 Elemento neutro: ¿de dónde "arranco"? La unión parte del conjunto vacío y le agrega todo lo de A y todo lo de B: el vacío es su elemento neutro (unir con vacío no cambia nada). La intersección y la diferencia, en cambio, no arrancan del vacío como base de recorrido: recorren el primer conjunto (A) y deciden, elemento por elemento, si lo conservan según el segundo (B). El resultado r sí empieza vacío en los tres casos, pero lo que se recorre es distinto.

4. Costo

inicializarConjuntoO(1)O(1)
agregarO(n)O(n)

agregar, sacar y pertenece son O(n) porque hay que buscar el elemento recorriendo toda la estructura (y agregar, además, llama internamente a pertenece). En cambio, conjuntoVacío y elegir son O(1): no recorren nada.

💡 ¿Y si quiero que sea rápido? Estas implementaciones son comparativamente ineficientes justamente por esa búsqueda lineal. Para conjuntos grandes, la estructura ideal es un hashmap, que lleva agregar, sacar y pertenece a O(1) promedio.

5. Errores comunes

⚠️ Agregar sin chequear pertenece Si agregar no verifica if (!pertenece(x)), entran duplicados y se rompe la definición de conjunto. La verificación no es opcional: es parte de la operación.
⚠️ Violar la precondición de elegir / sacar Llamar elegir() con el conjunto vacío rompe el programa (NullPointerException en LD; en arreglo, cant es 0 y el índice queda mal). La precondición de elegir() es conjunto no vacío.
⚠️ En arreglo: no "compactar" al sacar En ConjuntoAR.sacar, hay que mover el último elemento a la posición liberada (arr[i] = arr[cant-1]) y bajar cant. Si te olvidás de pisar el hueco o de decrementar cant, te quedan basura o repetidos en el arreglo.
💡 Tip de parcial Como no hay orden, mover el último al hueco es válido y barato: no hace falta desplazar el resto del arreglo. Aprovechalo.

6. Resumen

  • Sin repetidos y sin orden: lo único que importa es la pertenencia.
  • Operaciones: agregar, sacar, pertenece, elegir, conjuntoVacío, inicializarConjunto.
  • Para evitar duplicados, agregar chequea pertenece antes de insertar.
  • agregar, sacar y pertenece son O(n) (hay que buscar); conjuntoVacío y elegir son O(1).
  • En arreglo, al sacar se reemplaza por el último elemento: no hace falta desplazar nada.

7. Laboratorio: conjunto al azar

Probá en vivo las dos cosas que más confunden del conjunto: que elegir() es aleatorio (no devuelve "el primero") y que recorrerlo lo vacía. Agregá valores, sacá alguno, y después tocá “Recorrer (elegir + sacar)”: vas a ver que el orden en que salen las fichas es impredecible y que al final el conjunto queda vacío. Compará con “Iterar SIN destruir”, que recorre una copia y deja el conjunto original intacto.
