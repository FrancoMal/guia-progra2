Cola de Prioridad

1. ¿Qué es y cuándo se usa?

Una cola de prioridad es como una cola común, pero cada elemento entra con una prioridad asociada. La diferencia es que no sale primero el que llegó primero (FIFO), sino el de mayor prioridad. Si dos tienen la misma prioridad, en esta guía respetamos entre ellos el orden de llegada (ver la aclaración sobre empates más abajo).

Analogía: la guardia de un hospital. No te atienden por orden de llegada, sino por gravedad — el caso más urgente pasa primero, aunque haya llegado último.

Se usa para: planificación de tareas (scheduling), algoritmos de grafos como Dijkstra, y en general cuando hay que atender pedidos según importancia y no según el orden de llegada.

primero → (9, p8)→ (4, p5)→ (7, p2)→ null

Cada nodo guarda un valor y su prioridad. En el diagrama, (9, p8) es el de mayor prioridad y por eso quedó primero.

2. Interfaz del TDA

Las operaciones del TDA Cola de Prioridad y sus precondiciones:

public interface ColaPrioridadTDA {
    void inicializarCola();                       // Sin precondiciones.
    void acolarPrioridad(int x, int prioridad);   // Cola inicializada.
    void desacolar();                             // Cola inicializada y no vacía.
    int primero();                                // Cola inicializada y no vacía.
    int prioridad();                              // Cola inicializada y no vacía.
    boolean colaVacia();                          // Cola inicializada.
}

acolarPrioridad agrega el valor x con la prioridad indicada. primero() devuelve el valor del elemento de mayor prioridad y prioridad() devuelve su prioridad; ninguno de los dos lo saca de la cola (para eso está desacolar()).

3. Implementaciones

Con lista dinámica ordenada por prioridad (LD)

La lista se mantiene ordenada por prioridad de mayor a menor: el nodo de mayor prioridad es siempre el primero. Así, primero(), prioridad() y desacolar() trabajan directamente sobre primero y son O(1). El costo se paga al insertar: hay que recorrer la lista para dejar el nuevo nodo en su lugar.

public class ColaPrioridadLD implements ColaPrioridadTDA {

    class NodoPrioridad {   // Cada nodo guarda un valor, su prioridad y la referencia al siguiente.
        int valor;
        int prioridad;
        NodoPrioridad sig;
    }

    NodoPrioridad primero;  // Referencia al primer nodo: el de MAYOR prioridad de la cola.

    public void inicializarCola() {
        primero = null;     // Cola vacía = lista vacía (null).
    }

    public void acolarPrioridad(int x, int prioridad) {
        NodoPrioridad nuevo = new NodoPrioridad();   // Creación de un nuevo nodo.
        nuevo.valor = x;
        nuevo.prioridad = prioridad;
        if (primero == null || prioridad > primero.prioridad) {
            // Caso especial: el nuevo va al frente (cola vacía o supera al actual primero).
            nuevo.sig = primero;
            primero = nuevo;
        } else {
            // Si no, hay que recorrer la cola buscando la posición correcta.
            NodoPrioridad turista = primero;   // Nodo "turista" que recorre mirando al siguiente.
            while (turista.sig != null && turista.sig.prioridad >= prioridad)
                turista = turista.sig;
            nuevo.sig = turista.sig;   // Se engancha el nuevo entre "turista" y su siguiente.
            turista.sig = nuevo;
        }
    }

    public void desacolar() {       // Sale el primer elemento (el de mayor prioridad).
        primero = primero.sig;      // El segundo nodo pasa a ser el primero.
    }

    public int primero() {
        return primero.valor;
    }

    public int prioridad() {
        return primero.prioridad;
    }

    public boolean colaVacia() {
        return (primero == null);
    }
}
💡 Cómo leer el acolarPrioridad Hay dos situaciones. (1) Insertar al frente: si la cola está vacía (primero == null) o el nuevo tiene más prioridad que el primero actual, el nuevo apunta al viejo primero y pasa a ser el primero. (2) Recorrer: en cualquier otro caso, el "turista" avanza mientras el siguiente exista y tenga prioridad mayor o igual a la del nuevo; cuando se detiene, el nuevo se engancha justo después del turista. La condición >= (mayor o igual) hace que, ante empate de prioridad, el nuevo quede detrás de los que ya estaban: respeta el orden de llegada.
📌 Empates: qué define el TDA y qué no El TDA puro de cola de prioridad no define el orden entre elementos de igual prioridad: solo garantiza que sale alguno de los de mayor prioridad. La regla "a igual prioridad, FIFO (gana el que llegó antes)" es la convención de esta guía (Wehbe), no es universal. Lo que decide el desempate es la comparación del acolarPrioridad: con >= el nuevo se mete detrás de los empatados (FIFO entre iguales); con > estricto, al no desplazar a quienes ya tenían esa prioridad, el nuevo se inserta delante de ellos y el orden de los empatados puede variar. Moraleja: si un ejercicio depende del orden entre prioridades iguales, fijate qué comparación usa la implementación.

Con dos arreglos en tándem (DA)

Otra opción es usar dos arreglos paralelos: uno de valores y otro de prioridades, que se modifican siempre juntos. Se mantiene ordenado por prioridad, y al insertar se hace un corrimiento hacia adelante hasta dejar el par en su posición.

public class ColaPrioridadDA implements ColaPrioridadTDA {

    int[] valores;       // El arreglo de valores.
    int[] prioridades;   // El arreglo de prioridades (se mueve en tándem con "valores").
    int cant;            // Cantidad de elementos; "cant" apunta a la primera posición libre.
    int max = 40;        // Cantidad máxima de elementos.

    public void inicializarCola() {
        valores = new int[max];
        prioridades = new int[max];
        cant = 0;
    }

    public void acolarPrioridad(int x, int prioridad) {
        int i = cant;
        // Se recorre "prioridades" hacia atrás con corrimiento hasta encontrar la posición.
        while (i > 0 && prioridades[i-1] > prioridad) {
            valores[i] = valores[i-1];
            prioridades[i] = prioridades[i-1];
            i--;
        }
        valores[i] = x;             // Se inserta el nuevo par en la posición encontrada.
        prioridades[i] = prioridad;
        cant++;
    }

    public void desacolar() {
        cant--;   // Eliminación lógica: el par de la última posición sale de la cola.
    }

    public int primero() {
        return valores[cant-1];     // El de mayor prioridad quedó al final del arreglo.
    }

    public int prioridad() {
        return prioridades[cant-1];
    }

    public boolean colaVacia() {
        return (cant == 0);
    }
}

Con arreglo de objetos ordenado (AO)

Variante de la anterior: en vez de dos arreglos, se usa un solo arreglo de objetos, donde cada objeto Elemento agrupa el par valor-prioridad. La lógica de inserción con corrimiento es la misma; el de mayor prioridad queda al final.

public class ColaPrioridadAO implements ColaPrioridadTDA {

    class Elemento {     // Un "estuche" que agrupa un par valor-prioridad.
        int valor;
        int prioridad;
    }

    Elemento[] pares;    // El elemento de mayor prioridad queda al final del arreglo.
    int cant;

    public void inicializarCola() {
        pares = new Elemento[20];
        cant = 0;
    }

    public void acolarPrioridad(int x, int prioridad) {
        int i = cant;
        // Se recorre el arreglo hacia atrás con corrimiento hasta encontrar la posición.
        while (i > 0 && pares[i-1].prioridad > prioridad) {
            pares[i] = pares[i-1];
            i--;
        }
        pares[i] = new Elemento();   // Se inserta el nuevo par en la posición encontrada.
        pares[i].valor = x;
        pares[i].prioridad = prioridad;
        cant++;
    }

    public void desacolar() {
        cant--;   // Eliminación lógica.
    }

    public int primero() {
        return pares[cant-1].valor;
    }

    public int prioridad() {
        return pares[cant-1].prioridad;
    }

    public boolean colaVacia() {
        return (cant == 0);
    }
}
💡 ¿Dónde queda el de mayor prioridad? Ojo con la convención: en la LD el de mayor prioridad está al frente (es primero), mientras que en los arreglos (DA y AO) queda al final (posición cant-1). En ambos casos sale en O(1), solo cambia de qué punta lo sacás. Estas implementaciones con arreglo ordenado son simples pero ineficientes al insertar; lo ideal para una cola de prioridad de verdad sería un heap.

Ordenar con una cola de prioridad

Una cola de prioridad es, en el fondo, un ordenamiento por inserción: cada acolarPrioridad mete el elemento en su lugar dentro de la estructura ya ordenada. Eso da un truco simple para ordenar un conjunto de números: encolá cada número usando su propio valor como prioridad y después desacolá todo. Como sale primero el de mayor prioridad, los valores salen ordenados de mayor a menor.

// Ordena el arreglo "nums" de mayor a menor usando una cola de prioridad.
ColaPrioridadTDA c = new ColaPrioridadLD();
c.inicializarCola();
for (int i = 0; i < nums.length; i++)
    c.acolarPrioridad(nums[i], nums[i]);   // prioridad = el propio valor
while (!c.colaVacia()) {
    System.out.println(c.primero());       // van saliendo de mayor a menor
    c.desacolar();
}

El mismo truco sirve para ordenar una pila: vaciás la pila (con desapilar) y vas volcando cada elemento a una cola de prioridad usando su valor como prioridad; cuando la pila quedó vacía, desacolás todo y obtenés los elementos ordenados. Es una forma cómoda de ordenar sin tocar la pila original.

💡 ¿Y por qué no es el mejor ordenamiento? Como cada acolarPrioridad es O(n), encolar n elementos cuesta O(n²): este "ordenamiento por cola de prioridad" es, en costo, un ordenamiento por inserción común. Sirve para entender la idea, pero no es el método más rápido para ordenar.
📌 La versión eficiente: con HEAP (montículo) Las implementaciones de esta guía mantienen la estructura ordenada, así que insertar cuesta O(n). Existe otra implementación, con un heap (montículo: un árbol binario casi completo con una condición de orden entre padre e hijos), que consigue acolarPrioridad y desacolar en O(log n) en lugar de O(n), sin tener que mantener todo totalmente ordenado. Es la forma "de verdad" de implementar una cola de prioridad; no la desarrollamos acá, pero conviene saber que existe y por qué es más eficiente.

El acolarPrioridad es O(n) porque, para mantener la estructura ordenada, en el peor caso hay que recorrerla entera buscando dónde va el nuevo elemento (en la LD, avanzando con el "turista"; en los arreglos, corriendo elementos). En cambio desacolar, primero, prioridad y colaVacia son O(1): como el de mayor prioridad ya está en una punta fija, se accede o se saca sin recorrer nada.

5. Errores comunes

⚠️ Violar la precondición Llamar desacolar(), primero() o prioridad() con la cola vacía rompe el programa: NullPointerException en LD, o índice -1 en los arreglos. Verificá siempre if (!colaVacia()) antes.
⚠️ Confundir el criterio No es FIFO: sale primero el de mayor prioridad, no el que llegó primero. Cuidado también con qué número significa "más prioritario" (acá, número más grande = más prioridad).
⚠️ Romper el enganche de sig (en la LD) Al insertar con el "turista" hay que hacer nuevo.sig = turista.sig antes de turista.sig = nuevo. Si invertís el orden, perdés la referencia al resto de la lista y se pierden todos los nodos que venían después.
💡 Tip de parcial Repasá el while del acolarPrioridad: la condición incluye turista.sig != null para no caerte del final de la lista, y turista.sig.prioridad >= prioridad para frenar en el lugar correcto.

6. Resumen

  • Como una cola, pero cada elemento tiene prioridad: sale primero el de mayor prioridad.
  • Operaciones: acolarPrioridad, desacolar, primero, prioridad, colaVacia, inicializarCola.
  • Implementaciones vistas: lista dinámica ordenada (LD) y arreglos ordenados (DA / AO).
  • Como se mantiene ordenada, acolarPrioridad es O(n) y el resto O(1).
  • Lo más eficiente para una cola de prioridad sería un heap, no un arreglo ordenado.
