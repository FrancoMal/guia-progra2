Pila (Stack)

1. ¿Qué es y cuándo se usa?

Una pila es una colección LIFO (Last In, First Out): el último elemento en entrar es el primero en salir. Analogía: una pila de platos — solo podés agarrar el de arriba, y para llegar a uno de abajo tenés que sacar los de encima.

Se usa para: deshacer/rehacer (undo), evaluación de expresiones y balanceo de paréntesis, y para entender cómo el sistema maneja las llamadas recursivas (la pila de ejecución).

tope → 7→ 3→ 5→ null

2. Interfaz del TDA

Las operaciones del TDA Pila y sus precondiciones:

public interface PilaTDA {
    void inicializarPila();   // Sin precondiciones.
    void apilar(int x);       // Pila inicializada.
    void desapilar();         // Pila inicializada y no vacía.
    int tope();               // Pila inicializada y no vacía.
    boolean pilaVacia();      // Pila inicializada.
}

3. Implementaciones

Con lista dinámica (LD)

El tope de la pila es el primer nodo de la lista enlazada. Apilar inserta adelante y desapilar saca el primero, así que todas las operaciones son O(1).

public class PilaLD implements PilaTDA {
    class Nodo { int valor; Nodo sig; }   // Cada nodo guarda un valor y apunta al siguiente.
    Nodo tope;                            // Referencia al primer nodo (el tope).

    public void inicializarPila() { tope = null; }      // Pila vacía = lista vacía (null).

    public void apilar(int x) {
        Nodo nuevo = new Nodo();
        nuevo.valor = x;
        nuevo.sig = tope;   // El nuevo apunta al viejo tope...
        tope = nuevo;       // ...y pasa a ser el nuevo tope.
    }

    public void desapilar() { tope = tope.sig; }        // El segundo nodo pasa a ser el tope.
    public int tope() { return tope.valor; }
    public boolean pilaVacia() { return tope == null; }
}

Con arreglo (A)

Se guarda un arreglo y un entero tope que indica la cantidad de elementos (y por lo tanto la próxima posición libre).

public class PilaA implements PilaTDA {
    int[] datos;
    int tope;   // Cantidad de elementos; el último válido está en datos[tope - 1].

    public void inicializarPila() { datos = new int[100]; tope = 0; }
    public void apilar(int x) { datos[tope] = x; tope++; }
    public void desapilar() { tope--; }
    public int tope() { return datos[tope - 1]; }
    public boolean pilaVacia() { return tope == 0; }
}
⚠️ Overflow del arreglo A diferencia de la lista dinámica, el arreglo tiene tamaño fijo. Si la pila ya está llena (tope == datos.length) y se llama a apilar(x), no hay posición libre: datos[tope] = x revienta con ArrayIndexOutOfBoundsException. Apilar con el arreglo lleno es una violación de precondición (no queda espacio). En un examen esto se chequea o se lanza un error explícito: 
public void apilar(int x) {
    if (tope == datos.length) throw new RuntimeException("Pila llena (overflow)");
    datos[tope] = x;
    tope++;
}

Recorrer una pila: es una estructura destructiva

📦 Estructura destructiva El TDA Pila no tiene iterador no destructivo: la única forma de leer todos sus elementos es ir desapilarándolos uno a uno hasta que pilaVacia()… pero al hacerlo la pila queda vacía. Si un método recibe una pila y no debe alterarla, hay que trabajar sobre una copia.

Dato fino: copiar una pila requiere 2 vuelcos, porque cada vuelco la invierte. Volcás la original a una auxiliar (queda al revés) y volcás la auxiliar a la copia (vuelve al orden original); de paso, así reconstruís también la original.

// Copia 'origen' en 'copia' dejando 'origen' como estaba. Dos vuelcos:
static void copiar(PilaTDA origen, PilaTDA copia) {
    PilaA aux = new PilaA();  aux.inicializarPila();
    copia.inicializarPila();
    while (!origen.pilaVacia()) {        // 1er vuelco: origen → aux (aux queda invertida)
        aux.apilar(origen.tope());
        origen.desapilar();
    }
    while (!aux.pilaVacia()) {           // 2do vuelco: aux → origen y copia (ambas al orden original)
        origen.apilar(aux.tope());
        copia.apilar(aux.tope());
        aux.desapilar();
    }
}

Invertir una pila por recursión

Un clásico de parcial que conecta pila con recursividad: invertir una pila usando solo recursión, sin estructuras auxiliares explícitas. La idea aprovecha que todas las llamadas recursivas comparten la misma pila: se saca el tope, se invierte el resto, y se reinserta el elemento sacado en el fondo con un helper insertarAlFondo (también recursivo).

// Invierte la pila p usando solo recursión.
static void invertir(PilaTDA p) {
    if (p.pilaVacia()) return;          // Caso base: nada que invertir.
    int x = p.tope();                   // Saco el tope...
    p.desapilar();
    invertir(p);                        // ...invierto lo que quedó (más chico → termina)...
    insertarAlFondo(p, x);              // ...y meto x en el FONDO de la pila ya invertida.
}

// Inserta x en el fondo de p (no en el tope), solo con recursión.
static void insertarAlFondo(PilaTDA p, int x) {
    if (p.pilaVacia()) {                // Caso base: pila vacía → el fondo es el tope.
        p.apilar(x);
        return;
    }
    int t = p.tope();                   // Aparto el tope actual...
    p.desapilar();
    insertarAlFondo(p, x);              // ...bajo x hasta el fondo...
    p.apilar(t);                        // ...y al volver, repongo cada elemento encima.
}
💡 Por qué funciona Cada llamada a invertir saca un elemento y deja la pila más chica, así que la recursión avanza hacia el caso base. insertarAlFondo baja el valor hasta lo más profundo apartando los elementos de arriba en la propia pila (de ahí que no haga falta una estructura auxiliar) y los repone al regresar de cada llamada.

5. Errores comunes

⚠️ Violar la precondición Llamar desapilar() o tope() con la pila vacía rompe el programa: NullPointerException en LD, o índice -1 en arreglo.
⚠️ No inicializar Usar la pila sin llamar antes a inicializarPila() deja tope en un estado inválido.
💡 Tip de parcial Antes de desapilar() o tope(), verificá siempre if (!pilaVacia()).

6. Resumen

  • LIFO: el último en entrar es el primero en salir.
  • Operaciones: apilar, desapilar, tope, pilaVacia, inicializarPila.
  • Todas O(1) tanto en lista dinámica como en arreglo.
  • Se trabaja siempre por un solo extremo (el tope).
