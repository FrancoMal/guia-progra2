Cola (Queue)

1. ¿Qué es y cuándo se usa?

Una cola es una colección FIFO (First In, First Out): el primer elemento en entrar es el primero en salir. Analogía: la fila del banco — el primero que llega es el primero que lo atienden, y los nuevos se forman atrás.

Se usa para: procesar pedidos en el orden en que llegan (impresoras, tareas), buffers de datos productor-consumidor, y recorridos por niveles como BFS (búsqueda en anchura) en grafos y árboles.

2. Interfaz del TDA

Las operaciones del TDA Cola y sus precondiciones:

public interface ColaTDA {
    void inicializarCola();   // Sin precondiciones.
    void acolar(int x);       // Cola inicializada.
    void desacolar();         // Cola inicializada y no vacía.
    int primero();            // Cola inicializada y no vacía.
    boolean colaVacia();      // Cola inicializada.
}

3. Implementaciones

Con lista dinámica (LD)

Se guardan dos referencias: primero (el frente, de donde se saca) y ultimo (el final, donde se agrega). Acolar inserta al final y desacolar saca del frente, así que todas las operaciones son O(1) sin recorrer la lista.

public class ColaLD implements ColaTDA {
    class Nodo { int valor; Nodo sig; }   // Cada nodo guarda un valor y apunta al siguiente.
    Nodo primero;                         // Frente: de aquí se desacola.
    Nodo ultimo;                          // Final: aquí se acola.

    public void inicializarCola() { primero = null; ultimo = null; }  // Cola vacía.

    public void acolar(int x) {
        Nodo nuevo = new Nodo();
        nuevo.valor = x;
        nuevo.sig = null;          // El nuevo queda al final, no apunta a nadie.
        if (colaVacia()) {
            primero = nuevo;       // Si estaba vacía, el nuevo es frente y final a la vez.
        } else {
            ultimo.sig = nuevo;    // El viejo final ahora apunta al nuevo...
        }
        ultimo = nuevo;            // ...y el nuevo pasa a ser el final.
    }

    public void desacolar() {
        primero = primero.sig;     // El segundo nodo pasa a ser el frente.
        if (primero == null) {
            ultimo = null;         // Si la cola quedó vacía, también limpiamos ultimo.
        }
    }

    public int primero() { return primero.valor; }
    public boolean colaVacia() { return primero == null; }
}

Con arreglo circular (A)

Se usa un arreglo y dos índices: frente (dónde está el primero) y fin (próxima posición libre). Para reutilizar las celdas que se van liberando al desacolar, los índices avanzan en círculo usando el operador módulo: fin = (fin + 1) % datos.length. Así el arreglo se comporta como un anillo y no se "agota" por un extremo. Se suele llevar también un contador de elementos para distinguir cola vacía de cola llena.

Cola circular sobre arreglo

La clave para que acolar y desacolar cuesten O(1) sobre un arreglo es no mover los datos: en vez de correr todo el arreglo, movemos los índices. Llevamos tres datos: ini (dónde está el primero), fin (próxima posición libre) y cant (cuántos elementos hay). Al acolar avanzamos fin; al desacolar avanzamos ini; y los dos avanzan en círculo con módulo, así que cuando llegan al borde vuelven a la posición 0 y reutilizan las celdas liberadas.

public class ColaCircular implements ColaTDA {
    int[] datos;
    int ini;    // Índice del frente (de aquí se desacola).
    int fin;    // Próxima posición libre (aquí se acola).
    int cant;   // Cantidad de elementos: distingue vacía (0) de llena (N).

    public void inicializarCola() {
        datos = new int[100];
        ini = 0; fin = 0; cant = 0;
    }

    public void acolar(int x) {
        datos[fin] = x;                 // Escribimos en la próxima libre...
        fin = (fin + 1) % datos.length; // ...y el índice avanza en círculo.
        cant++;
    }

    public void desacolar() {
        ini = (ini + 1) % datos.length; // El frente avanza en círculo; no movemos datos.
        cant--;
    }

    public int primero() { return datos[ini]; }
    public boolean colaVacia() { return cant == 0; }
}

Sin la aritmética módulo, un arreglo lineal se queda sin lugar por el extremo del final aunque haya celdas libres adelante (las que dejó desacolar). La alternativa lineal sería correr todos los elementos una posición hacia el frente en cada desacolar: eso recorre el arreglo y cuesta O(n). La versión circular evita ese corrimiento reusando las celdas con (idx + 1) % N, y por eso ambas operaciones quedan en O(1).

La cola es eficiente porque trabaja sobre dos extremos fijos (frente y final): teniendo las referencias primero y ultimo no hay que recorrer nada.

📐 Qué vs cómo (costo) El TDA define qué hace la cola (acolar, desacolar, primero, colaVacia) y es independiente de cómo se implementa. El costo, en cambio, depende del cómo: en un arreglo lineal sin índices circulares, desacolar puede costar O(n) porque hay que correr todos los elementos hacia el frente. Con una lista enlazada que guarda un puntero al último nodo (o con el arreglo circular), acolar y desacolar son O(1). Mismo TDA, distinto costo: lo que cambia es la estructura interna, no el contrato.
⚠️ Estructura destructiva Recorrer una cola la vacía: para mirar todos los elementos hay que desacolarlos, y al terminar la cola queda vacía. Si necesitás conservarla, trabajá sobre una copia. Detalle clave: copiar una cola necesita un solo vuelco — desacolás de la original y acolás en la copia, y el orden se preserva tal cual (a diferencia de la pila, que se invierte y necesita un vuelco extra para volver a quedar en orden).

5. Errores comunes

⚠️ Violar la precondición Llamar desacolar() o primero() con la cola vacía rompe el programa: NullPointerException en LD, o índices inválidos en el arreglo.
⚠️ Olvidar actualizar ultimo En lista dinámica, no poner ultimo = nuevo al acolar el primer elemento, o no limpiar ultimo = null cuando la cola queda vacía tras desacolar. Si ultimo apunta a un nodo viejo, el próximo acolar lo engancha mal.
💡 Tip de parcial Antes de desacolar() o primero(), verificá siempre if (!colaVacia()). Y al programar acolar/desacolar en LD, pensá explícitamente los casos de cola vacía y de un solo elemento.

6. Resumen

  • FIFO: el primero en entrar es el primero en salir.
  • Operaciones: acolar, desacolar, primero, colaVacia, inicializarCola.
  • Se acola por el final y se desacola por el frente.
  • Todas O(1) con punteros primero/ultimo (LD) o con arreglo circular.
