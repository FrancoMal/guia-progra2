Árboles (Binario, ABB, AVL)

1. ¿Qué es y cuándo se usa?

Un árbol es una estructura jerárquica: en vez de una secuencia lineal (como la pila o la lista), los datos se organizan en niveles. Un árbol binario es aquel donde cada nodo tiene a lo sumo dos hijos: el hijo izquierdo y el derecho.

Términos que tenés que tener claros para el parcial:

  • Raíz: el nodo de arriba de todo, el único sin padre.
  • Hoja: un nodo sin hijos (izquierdo y derecho en null).
  • Nodo interno: un nodo que sí tiene al menos un hijo (no es hoja). La raíz, si el árbol tiene más de un nodo, es interna.
  • Padre / hijo: si A apunta a B (por izq o der), A es el padre de B y B es hijo de A. Cada nodo tiene a lo sumo un padre.
  • Ancestros / descendientes: los ancestros de un nodo son su padre, el padre de su padre, etc., hasta la raíz. Los descendientes son todos los nodos que cuelgan de él (sus hijos, nietos, …).
  • Profundidad de un nodo: la longitud del camino desde la raíz hasta ese nodo. La raíz tiene profundidad 0; sus hijos, 1; sus nietos, 2; y así. Es una propiedad de cada nodo.
  • Altura: la longitud del camino más largo desde la raíz hasta una hoja. Es una propiedad del árbol entero (la profundidad máxima). No la confundas con la profundidad de un nodo puntual.
  • Subárbol: cualquier nodo junto con todos sus descendientes es, a su vez, un árbol.
📏 Profundidad vs. altura, con un ejemplo Tomá este ABB: raíz 8; a su izquierda 3; a la izquierda de 3, la hoja 1; y a la derecha de 8, la hoja 10.
  • Profundidad de 8 = 0 (es la raíz). Profundidad de 3 y 10 = 1. Profundidad de 1 = 2.
  • Altura del árbol = 2 (el camino más largo, 8 → 3 → 1, tiene 2 aristas).
La profundidad la mirás bajando desde la raíz a un nodo; la altura es la profundidad del nodo más hondo.

Según su forma, a un árbol binario lo clasificamos así:

  • Sesgado / degenerado: cada nodo tiene a lo sumo un hijo, así que se estira como una lista. Su altura es n − 1 (la peor posible). Es lo que pasa en un ABB si insertás valores ya ordenados.
  • Completo: todos los niveles están llenos salvo, quizás, el último, que se llena de izquierda a derecha.
  • Perfecto: todos los niveles, incluido el último, están completamente llenos. Un árbol perfecto de altura h tiene exactamente 2^(h+1) − 1 nodos.

Se usan para representar jerarquías (carpetas, organigramas), para búsquedas eficientes (el ABB) y como base de estructuras balanceadas (el AVL).

2. Ideas clave

Un nodo de árbol binario guarda un valor y dos referencias (a sus hijos):

class Nodo {
    int valor;        // El dato que guarda el nodo.
    Nodo izq, der;    // Hijos izquierdo y derecho (pueden ser null).
}

Tres ideas que aparecen una y otra vez:

  • Un árbol vacío es null. La raíz en null significa "no hay nada".
  • La mayoría de las operaciones son recursivas: resolvés el nodo actual y delegás en el subárbol izquierdo y el derecho.
  • El caso base casi siempre es "el nodo es null": ahí cortás la recursión.
📕 Modelo recursivo de Monzón Esta guía usa el modelo "Nodo con izq/der" (un nodo guarda un valor y dos referencias a nodos). El TDA BinaryTree que Monzón entrega impreso usa otro modelo, recursivo: el árbol es su raíz.
  • getRoot() devuelve el valor de la raíz (un int).
  • getLeft() / getRight() devuelven otro BinaryTree —el subárbol completo, o null si no hay—, no un valor.
  • addLeft(int) / addRight(int) crean una hoja hija y lanzan excepción si ya existe ese hijo (no pisan).
  • removeLeft() / removeRight() podan esa rama entera.
El caso base canónico de todo recorrido sobre este modelo es if (arbol == null || arbol.isEmpty()) return;. Como acá el subárbol es otro árbol, recursás pasando arbol.getLeft() y arbol.getRight() en vez de nodo.izq y nodo.der. La lógica es la misma; lo que cambia es quién viaja en la recursión: un subárbol entero, no una referencia a nodo.

3. Recorridos y operaciones (Java)

Recorridos

Recorrer es visitar todos los nodos. Según cuándo proceso la raíz respecto de sus hijos, hay tres recorridos. Todos son recursivos y comparten la misma estructura:

// Preorden: raíz, luego izquierda, luego derecha.
void preorden(Nodo nodo) {
    if (nodo == null) return;        // Caso base: subárbol vacío.
    System.out.print(nodo.valor + " ");
    preorden(nodo.izq);
    preorden(nodo.der);
}

// Inorden: izquierda, raíz, derecha.
void inorden(Nodo nodo) {
    if (nodo == null) return;
    inorden(nodo.izq);
    System.out.print(nodo.valor + " ");
    inorden(nodo.der);
}

// Postorden: izquierda, derecha, raíz.
void postorden(Nodo nodo) {
    if (nodo == null) return;
    postorden(nodo.izq);
    postorden(nodo.der);
    System.out.print(nodo.valor + " ");
}
💡 Tip de parcial En un ABB, el recorrido inorden imprime los valores ordenados de menor a mayor. Es una pregunta clásica.

Recorrido por niveles (BFS)

Preorden, inorden y postorden van en profundidad (se hunden por una rama antes de pasar a la siguiente). El recorrido por niveles hace lo contrario: visita primero la raíz, después todos los nodos de profundidad 1, luego los de profundidad 2, y así. Es el clásico BFS (breadth-first), y la mejor forma de hacerlo no es recursiva: se apoya en una Cola.

La idea: encolás la raíz; mientras la cola no esté vacía, desencolás un nodo, lo procesás y encolás sus hijos no nulos (primero el izquierdo, después el derecho). La cola garantiza el orden FIFO, que es justo el orden por niveles.

void porNiveles(Nodo raiz) {
    if (raiz == null) return;            // Árbol vacío: no hay nada que recorrer.
    Queue<Nodo> cola = new LinkedList<>();
    cola.add(raiz);                      // Arrancamos encolando la raíz.
    while (!cola.isEmpty()) {
        Nodo actual = cola.poll();       // Desencolamos (FIFO: sale el más viejo).
        System.out.print(actual.valor + " ");
        if (actual.izq != null) cola.add(actual.izq);   // Encolamos los hijos
        if (actual.der != null) cola.add(actual.der);   // que existan.
    }
}
💡 No todo recorrido es recursivo Los tres recorridos en profundidad salen naturales con recursión (la pila de llamadas hace el trabajo). El recorrido por niveles, en cambio, es iterativo y necesita una Cola explícita. Es un buen recordatorio de que recursión y recorrido no son lo mismo.

ABB (Árbol Binario de Búsqueda)

Un ABB es un árbol binario con una propiedad de orden: para cada nodo, todos los valores del subárbol izquierdo son menores y todos los del subárbol derecho son mayores. Esa propiedad es lo que permite buscar rápido: en cada paso descartás la mitad del árbol.

// Insertar respetando la propiedad de orden. Devuelve la (nueva) raíz del subárbol.
Nodo insertar(Nodo nodo, int x) {
    if (nodo == null) {              // Llegamos a un lugar vacío: ahí va el nuevo nodo.
        Nodo nuevo = new Nodo();
        nuevo.valor = x;
        return nuevo;
    }
    if (x < nodo.valor)              // Menor: va al subárbol izquierdo.
        nodo.izq = insertar(nodo.izq, x);
    else if (x > nodo.valor)         // Mayor: va al subárbol derecho.
        nodo.der = insertar(nodo.der, x);
    // Si x == nodo.valor no hacemos nada (no repetimos valores).
    return nodo;
}

// Buscar: true si x está en el árbol.
boolean buscar(Nodo nodo, int x) {
    if (nodo == null) return false;          // Caso base: no está.
    if (x == nodo.valor) return true;        // Lo encontramos.
    if (x < nodo.valor)
        return buscar(nodo.izq, x);          // Menor: seguimos por la izquierda.
    else
        return buscar(nodo.der, x);          // Mayor: seguimos por la derecha.
}

Fijate que tanto al insertar como al buscar, en cada nivel comparamos x && nodo.valor de forma similar y bajamos por un solo lado: izquierda si x < nodo.valor, derecha si x > nodo.valor.

Eliminar en un ABB

Borrar es la operación más delicada del ABB, porque hay que sacar el nodo sin romper la propiedad de orden. Primero bajamos buscando el valor (igual que en insertar); cuando lo encontramos, distinguimos tres casos según cuántos hijos tenga:

  • Hoja (sin hijos): se borra directamente devolviendo null en su lugar.
  • Un solo hijo: se reemplaza por ese hijo (el que no es null), que sube a ocupar el lugar.
  • Dos hijos: no podemos devolver null ni un solo hijo. La maniobra clásica es reemplazar el valor del nodo por el mayor del subárbol izquierdo (su antecesor inorden: el valor inmediatamente anterior en orden) y después borrar ese mayor recursivamente. Como el mayor del subárbol izquierdo es la hoja más a la derecha de ese subárbol, su borrado cae siempre en el caso 1 o el 2.
// Elimina x del ABB. Devuelve la (nueva) raíz del subárbol.
Nodo eliminar(Nodo nodo, int x) {
    if (nodo == null) return null;           // No está: no hay nada que borrar.

    if (x < nodo.valor)                       // Bajamos buscando x, como en insertar/buscar.
        nodo.izq = eliminar(nodo.izq, x);
    else if (x > nodo.valor)
        nodo.der = eliminar(nodo.der, x);
    else {                                    // ¡Encontramos el nodo a borrar!
        // Caso 1 y 2: cero o un solo hijo → devolvemos el hijo que exista (o null).
        if (nodo.izq == null) return nodo.der;
        if (nodo.der == null) return nodo.izq;

        // Caso 3: dos hijos. Reemplazamos por el MAYOR del subárbol izquierdo
        // (antecesor inorden) y lo borramos de ese subárbol.
        int reemplazo = mayor(nodo.izq);
        nodo.valor = reemplazo;
        nodo.izq = eliminar(nodo.izq, reemplazo);
    }
    return nodo;
}

// Mayor valor de un subárbol: bajamos siempre por la derecha hasta la última hoja.
int mayor(Nodo nodo) {
    while (nodo.der != null) nodo = nodo.der;
    return nodo.valor;
}
💡 Por qué el antecesor inorden El mayor del subárbol izquierdo es menor que todo lo que está a la derecha del nodo y mayor que todo el resto del subárbol izquierdo: por eso, al ponerlo en lugar del nodo borrado, la propiedad de orden del ABB se mantiene intacta. (Simétricamente, también vale usar el sucesor inorden: el menor del subárbol derecho.)

AVL (ABB balanceado)

El problema del ABB es que su eficiencia depende de la forma. Si insertás valores ya ordenados (1, 2, 3, 4, …), cada nodo cuelga a la derecha del anterior y el árbol degenera en una lista: buscar pasa a costar O(n).

Un AVL es un ABB que se mantiene balanceado automáticamente. Después de cada inserción (o borrado), comprueba que para cada nodo las alturas de sus subárboles izquierdo y derecho no difieran en más de 1. Si se desbalancea, aplica rotaciones: operaciones locales que reacomodan unos pocos nodos para volver a balancear, sin romper la propiedad de orden del ABB.

Factor de equilibrio (FE)

El AVL se define con un número concreto por nodo, el factor de equilibrio:

FE(nodo) = altura(nodo.der) - altura(nodo.izq)

Un AVL es válido cuando todos sus nodos tienen FE ∈ {-1, 0, +1}. El signo te dice para qué lado pesa:

  • FE = 0: equilibrado, ambos lados igual de altos.
  • FE = +1: pesa un poco a la derecha (todavía válido).
  • FE = -1: pesa un poco a la izquierda (todavía válido).
  • FE = +2 o FE = -2: desbalanceado → hay que rotar.

Qué rotación aplicar: regla del signo

Cuando una inserción deja un nodo con FE = ±2, mirás el signo del nodo desbalanceado y el signo de su hijo del lado pesado. Con eso decidís de una:

  • Mismo signo (ambos + o ambos −) → rotación SIMPLE: RR si ambos son + (caso derecha-derecha), LL si ambos son − (caso izquierda-izquierda).
  • Signo distinto (uno + y el otro −) → rotación DOBLE: RL si el nodo es + y el hijo −; LR si el nodo es − y el hijo +. Una doble es, en realidad, dos simples encadenadas.

Lo importante para el parcial: una sola inserción rompe el balance en a lo sumo un nodo (el ancestro desbalanceado más cercano), y se arregla con a lo sumo 2 rotaciones (1 si es simple, 2 si es doble). Por eso reequilibrar cuesta O(1) y el AVL mantiene su altura en O(log n).

Mini-ejemplo: insertar 1, 2, 3

Insertamos en orden creciente en un AVL vacío. Al meter el 3, la raíz 1 queda con FE = +2 y su hijo del lado pesado (2) con FE = +1: mismo signo → rotación simple RR. El 2 sube a la raíz:

ANTES — raíz: 1 (FE=+2)→ der: 2 (FE=+1)→ der: 3
DESPUÉS — raíz: 2 (FE=0)→ izq: 1→ der: 3

Con una sola rotación pasamos de una lista degenerada (altura 2) a un árbol perfecto (altura 1), sin tocar la propiedad de orden: el inorden sigue dando 1 2 3.

💡 Por qué importa el balance Manteniendo la altura cercana a log n, el AVL garantiza que buscar e insertar sean O(log n) siempre, incluso en el peor caso. Es la diferencia entre descartar la mitad del árbol en cada paso o tener que recorrerlo entero.

4. Costo

OperaciónABB balanceado / AVLABB peor caso (degenerado)
buscarO(log n)O(n)
insertarO(log n)O(n)
recorridos (pre/in/postorden)O(n)O(n)

La clave: en un ABB balanceado, buscar e insertar son O(log n) porque en cada nivel descartás la mitad. En el peor caso (un ABB degenerado en lista), caen a O(n). El AVL garantiza O(log n) justamente porque nunca deja que eso pase. Los recorridos siempre son O(n): visitan todos los nodos sí o sí.

5. Errores comunes

⚠️ Olvidar el caso base Si no chequeás if (nodo == null) return ... al principio de cada método recursivo, al llegar a una hoja vas a acceder a nodo.izq o nodo.valor sobre null y explota con NullPointerException.
⚠️ Romper la propiedad del ABB Insertar a mano por el lado equivocado (un menor a la derecha, o un mayor a la izquierda) deja el árbol inconsistente: la búsqueda dejará de encontrar valores que sí están.
⚠️ Suponer O(log n) en un ABB cualquiera Un ABB no es O(log n) por definición. Solo lo es si está balanceado. Si los datos entran ordenados, degenera en lista y buscar cuesta O(n). Esa garantía la da el AVL.

6. Resumen

  • Árbol binario: estructura jerárquica donde cada nodo tiene a lo sumo dos hijos (izq, der).
  • Un árbol vacío es null; las operaciones son recursivas con caso base "nodo null".
  • Recorridos: preorden, inorden y postorden (en profundidad, recursivos) más el recorrido por niveles (BFS, iterativo con una Cola), todos O(n). El inorden de un ABB sale ordenado.
  • ABB: propiedad de orden (izquierda menores, derecha mayores) ⇒ buscar e insertar O(log n) si está balanceado, O(n) en el peor caso. Para eliminar con dos hijos, se reemplaza por el mayor del subárbol izquierdo (antecesor inorden).
  • AVL: ABB que se rebalancea con rotaciones. FE = altura(der) − altura(izq) debe quedar en {-1, 0, +1}; mismo signo ⇒ rotación simple, signo distinto ⇒ rotación doble (a lo sumo 2 por inserción) ⇒ garantiza O(log n).
