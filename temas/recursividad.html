Recursividad

1. ¿Qué es y cuándo se usa?

La recursividad es cuando una función se llama a sí misma para resolver un problema. La idea es descomponer el problema en una versión más chica del mismo problema, hasta llegar a un caso tan simple que se resuelve directo.

Se usa cuando un problema se define naturalmente en términos de sí mismo: factorial, sumas, Fibonacci, recorrer estructuras enlazadas o árboles. Cada llamada resuelve un cachito y delega el resto a otra llamada más chica.

factorial(3)→ factorial(2)→ factorial(1)→ factorial(0) = 1

2. Ideas clave

Toda recursión bien hecha tiene dos partes:

  • Caso base: la condición que corta la recursión. Es el problema más chico, que se resuelve sin volver a llamarse (ej: factorial(0) = 1).
  • Caso recursivo: la función se llama a sí misma con una entrada más chica, acercándose al caso base.

Cada llamada se apila en la pila de ejecución: queda "esperando" hasta que la llamada de adentro devuelve su resultado. Cuando se llega al caso base, las llamadas se van resolviendo al volver (desapilando), de adentro hacia afuera.

3 × factorial(2)→ 2 × factorial(1)→ 1 × factorial(0)→ vuelve: 1 → 1 → 2 → 6

3. Ejemplos en Java

Factorial

El caso base es n == 0 (vale 1); el recursivo multiplica n por el factorial de n - 1.

public int factorial(int n) {
    if (n == 0) return 1;            // Caso base: corta la recursión.
    return n * factorial(n - 1);     // Caso recursivo: problema más chico.
}

Suma de 1 a n

Misma estructura: el caso base devuelve 0; el recursivo suma n a la suma de 1..(n-1).

public int suma(int n) {
    if (n == 0) return 0;            // Caso base.
    return n + suma(n - 1);          // n + (n-1) + ... + 1.
}

Fibonacci

Tiene dos casos base (n == 0 y n == 1) y el caso recursivo hace dos llamadas: por eso es caro (ver costo).

public int fib(int n) {
    if (n <= 1) return n;            // fib(0)=0, fib(1)=1.
    return fib(n - 1) + fib(n - 2);  // Dos llamadas por cada nivel.
}

Recorrer y contar una lista enlazada

El caso base es la lista vacía (nodo == null devuelve 0); el recursivo cuenta 1 más lo que tenga el resto de la lista.

class Nodo { int valor; Nodo sig; }

public int contar(Nodo nodo) {
    if (nodo == null) return 0;          // Caso base: se acabó la lista.
    return 1 + contar(nodo.sig);         // 1 (este nodo) + el resto.
}

Recursión sobre árboles (plantillas)

Un árbol es una estructura recursiva por naturaleza: cada nodo tiene un subárbol izquierdo y uno derecho, que a su vez son árboles. Por eso casi todo recorrido se escribe con el patrón canónico: caso base cuando el nodo es null, y caso recursivo que combina el resultado de la izquierda con el de la derecha. Cambia solo cómo se combinan.

Asumimos un nodo así (igual al del tema de árboles):

class NodoArbol {
    int valor;
    NodoArbol izq;   // Subárbol izquierdo (otro árbol).
    NodoArbol der;   // Subárbol derecho.
}

Contar nodos. El caso base (árbol vacío) aporta 0; cada nodo aporta 1 más lo que cuenten sus dos subárboles.

public int contarNodos(NodoArbol nodo) {
    if (nodo == null) return 0;                              // Caso base: árbol vacío.
    return 1 + contarNodos(nodo.izq) + contarNodos(nodo.der); // Este + izquierda + derecha.
}

Altura. Un árbol vacío mide 0 (o −1 según la convención; acá usamos 0). Cada nodo suma 1 al más alto de sus dos subárboles.

public int altura(NodoArbol nodo) {
    if (nodo == null) return 0;                              // Caso base: no hay nivel.
    return 1 + Math.max(altura(nodo.izq), altura(nodo.der)); // 1 + el subárbol más alto.
}

Suma de los valores. Misma plantilla: el vacío aporta 0; cada nodo suma su valor a la suma de izquierda y derecha.

public int sumar(NodoArbol nodo) {
    if (nodo == null) return 0;                              // Caso base.
    return nodo.valor + sumar(nodo.izq) + sumar(nodo.der);   // valor + izquierda + derecha.
}

Devolver un conjunto con los nodos que cumplen una condición. En vez de combinar con +, combinamos uniendo conjuntos: armo el conjunto del subárbol izquierdo, le hago la unión con el del derecho y, si este nodo cumple, lo agrego. El caso base devuelve el conjunto vacío.

// Devuelve un ConjuntoTDA con los valores pares del árbol.
public ConjuntoTDA pares(NodoArbol nodo) {
    ConjuntoTDA c = new ConjuntoEstatico();   // Implementación concreta del TDA.
    c.inicializarConjunto();
    if (nodo == null) return c;               // Caso base: conjunto vacío.

    ConjuntoTDA izq = pares(nodo.izq);        // Conjunto del subárbol izquierdo.
    ConjuntoTDA der = pares(nodo.der);        // Conjunto del subárbol derecho.
    c = union(c, union(izq, der));            // Combino: uno los dos subárboles.

    if (nodo.valor % 2 == 0)                  // Si este nodo cumple la condición...
        c.agregar(nodo.valor);                // ...lo agrego al conjunto.
    return c;
}

Fijate que es la misma estructura que contarNodos: caso base que devuelve el "neutro" (0 o conjunto vacío) y un caso recursivo que combina izquierda y derecha. Solo cambia la operación de combinar (+ vs. union) y el dato neutro.

💡 La plantilla mental Para cualquier pregunta sobre un árbol ("¿cuántos…?", "¿la suma de…?", "¿el más alto…?", "¿qué nodos cumplen…?") arrancá igual: if (nodo == null) return NEUTRO; y después combiná el resultado de nodo.izq con el de nodo.der, sumando lo que aporta el nodo actual.

4. Costo

La recursión lineal (una sola llamada por nivel) hace n llamadas: es O(n). Fibonacci recursivo hace dos llamadas por nivel, y el árbol de llamadas se duplica en cada paso: O(2n).

AlgoritmoVersiónCosto
factorial(n)Recursiva linealO(n)
suma(n)Recursiva linealO(n)
contar(lista)Recursiva linealO(n)
fib(n)Recursiva (2 llamadas)O(2n)
fib(n)IterativaO(n)

¿Por qué el Fibonacci recursivo es tan caro? Porque repite cálculos: para calcular fib(5) calcula fib(3) varias veces desde cero.

fib(4)→ fib(3) + fib(2)→ fib(2) se calcula 2 veces

La versión iterativa guarda los dos valores anteriores y recorre una sola vez, así que es O(n):

public int fibIterativo(int n) {
    if (n <= 1) return n;
    int a = 0, b = 1;
    for (int i = 2; i <= n; i++) {   // Una sola pasada.
        int sig = a + b;
        a = b;
        b = sig;
    }
    return b;
}

Costo de la recursión

Hasta acá miramos el costo en tiempo (cuántas operaciones). Pero la recursión tiene además un costo en espacio que la iteración no paga: cada llamada viva ocupa un lugar en la pila de ejecución. Mientras una llamada está "esperando" el resultado de la de adentro, su marco (parámetros, variables, dónde volver) queda apilado.

Entonces el costo espacial es O(profundidad de la recursión): la cantidad máxima de llamadas apiladas a la vez. En cambio, la versión iterativa usa unas pocas variables y es O(1) en espacio.

CasoProfundidad máximaCosto espacial
factorial(n), suma(n), lista enlazadan llamadas anidadasO(n)
Recorrido recursivo de un árboltan profundo como la alturaO(altura)
Cualquier versión iterativa equivalenteno se apila nadaO(1)

En un árbol, la pila no crece con la cantidad de nodos sino con la altura: la recursión baja por una rama, apila hasta la hoja y va desapilando al volver. Un árbol balanceado de n nodos tiene altura ~log n, así que usa poca pila; uno degenerado (todo hacia un lado) tiene altura n y se comporta como una lista.

⚠️ StackOverflow por pila llena Si el caso base no se alcanza, las llamadas se apilan sin fin hasta que la pila se llena y salta StackOverflowError. Por eso importa la precondición: garantizar que cada llamada acerca la entrada al caso base. Incluso una recursión correcta puede desbordar la pila si la profundidad es enorme (por ejemplo, recorrer recursivamente una lista de millones de elementos).
⚠️ Fibonacci: árbol de llamadas duplicadas El Fibonacci recursivo no es caro por la pila (su profundidad es solo n), sino por el tiempo: cada nivel dispara dos llamadas y el árbol de llamadas se duplica en cada paso, recalculando los mismos valores una y otra vez. Eso da O(2n) en tiempo, frente a O(n) de la versión iterativa.

5. Errores comunes

⚠️ Olvidar el caso base Si no hay caso base (o nunca se alcanza), la función se llama infinitas veces, la pila de ejecución se llena y salta StackOverflowError.
⚠️ No reducir el problema El caso recursivo tiene que llamarse con una entrada más chica. Si llamás factorial(n) en lugar de factorial(n - 1), nunca te acercás al caso base → StackOverflowError.
💡 Tip de parcial Antes de dar por buena una recursión, preguntate dos cosas: ¿hay un caso base alcanzable? ¿cada llamada acerca la entrada a ese caso base? Si las dos dan que sí, termina.

6. Resumen

  • Una función recursiva se llama a sí misma con un problema más chico.
  • Necesita caso base (corta) y caso recursivo (reduce el problema).
  • Cada llamada se apila y se resuelve al volver del caso base.
  • Recursión lineal: O(n). Fibonacci recursivo: O(2n) vs iterativo O(n).
  • Sin caso base alcanzable o sin reducir el problema → StackOverflowError.
