Complejidad y Big-O

1. ¿Qué es y cuándo se usa?

La complejidad es una forma de medir cómo crece el costo de un algoritmo (la cantidad de operaciones, y por lo tanto el tiempo) a medida que crece el tamaño de la entrada, que llamamos n. La notación Big-O (o "O grande") describe ese crecimiento en el peor caso.

Se usa para comparar algoritmos sin tener que ejecutarlos: nos dice si una solución va a seguir siendo rápida cuando n sea grande (mil, un millón de datos) o si se va a volver impracticable. Analogía: no importa cuánto tarde en buscar en una agenda de 10 contactos; importa qué pasa cuando tenés 10 millones.

O(1)→ O(log n)→ O(n)→ O(n²)→ O(2ⁿ)

2. Ideas clave

Big-O no mide el tiempo exacto en segundos, sino el ritmo de crecimiento. Por eso hacemos dos simplificaciones:

  • Se ignoran las constantes: 3n y n crecen igual de rápido, así que ambos son O(n). Da lo mismo el "3".
  • Se ignoran los términos de menor orden: en 3n + 5, cuando n es grande el +5 es despreciable ⇒ queda O(n). En n² + n manda el n² ⇒ O(n²).
  • Lo que importa es el término que más crece, no el valor exacto del conteo.
💡 Regla práctica Contá las operaciones, quedate con el término dominante y borrá los números que lo multiplican o suman: 5n² + 100n + 30 ⇒ O(n²).

El vocabulario C / L / P de la cátedra

En la cursada, para clasificar un algoritmo no hace falta escribir la O grande completa: alcanza con decir si es C, L o P. Es la misma idea de Big-O, pero en tres categorías gruesas:

LetraCategoríaBig-O equivalenteEjemplo típico
CConstante≈ O(1)Acceder a arr[i], tope de una pila, un if sin bucles
LLineal≈ O(n)Recorrer una lista una vez
PPolinómico≈ O(n²) o más (O(n³), …)Dos o más bucles anidados sobre n
📋 Qué se pide (y qué no) En el parcial alcanza con clasificar (C, L o P) y justificar contando bucles. No se piden demostraciones formales con límites, ni encontrar la constante c ni el n₀ de la definición matemática de Big-O. Eso es teoría que no se evalúa: lo importante es razonar el orden de crecimiento.

Dos precisiones que se evalúan

🎯 Siempre se analiza el PEOR caso Aunque a veces el algoritmo termine antes, la clasificación se hace sobre el peor escenario posible. La búsqueda lineal es L (≈ O(n)) aunque a veces acierte en el primer intento: ese golpe de suerte es el mejor caso, no el que define el orden.
🎯 El número literal de vueltas NO importa: importa n La complejidad mide cómo crece el costo con el tamaño de la entrada (n), no cuántas veces gira un bucle según un número fijo. Por eso un for (int i = 0; i < 5; i++) es C / O(1), no lineal: hace 5 vueltas siempre, no dependen de n. En cambio for (int i = 0; i < n; i++) es L / O(n), porque las vueltas crecen con la entrada.

3. Órdenes comunes (con ejemplos)

Estos son los órdenes que más aparecen, de más rápido (mejor) a más lento (peor):

OrdenNombreEjemplo típicoQué tan rápido crece
O(1)ConstanteAcceder a arr[i], tope de una pilaNo crece: siempre el mismo costo
O(log n)LogarítmicoBúsqueda binaria en un arreglo ordenadoMuy lento: duplicar n suma 1 paso
O(n)LinealRecorrer una lista buscando un valorProporcional: el doble de datos, el doble de trabajo
O(n log n)Lineal-logarítmicoOrdenamientos eficientes (mergesort)Algo más que lineal, pero manejable
O(n²)CuadráticoDos bucles anidados (comparar todos contra todos)Rápido: el doble de datos, cuatro veces el trabajo
O(2ⁿ)ExponencialProbar todos los subconjuntos (fuerza bruta)Explota: un dato más duplica el trabajo

Para que se note la diferencia: con n = 1.000.000, un algoritmo O(n) hace un millón de pasos, pero uno O(n²) haría un billón. El O(log n), en cambio, hace apenas unos 20.

4. Cómo calcular el costo

La idea es contar cuántas veces se ejecuta lo que está adentro de los bucles, en función de n. Tres reglas alcanzan para la mayoría de los casos del parcial.

Un bucle simple → O(n)

Un bucle que recorre los n elementos una vez ejecuta el cuerpo n veces.

int suma = 0;
for (int i = 0; i < n; i++) {   // Se repite n veces.
    suma = suma + i;             // Operación O(1) hecha n veces ⇒ O(n).
}

Bucles anidados → se MULTIPLICAN → O(n²)

Si un bucle de n está adentro de otro bucle de n, el cuerpo se ejecuta n × n = n² veces. Los costos anidados se multiplican.

for (int i = 0; i < n; i++) {       // n veces...
    for (int j = 0; j < n; j++) {   // ...por cada i, otras n veces.
        System.out.println(i + "," + j);   // Se ejecuta n * n = n² veces ⇒ O(n²).
    }
}

Dividir a la mitad en cada paso → O(log n)

Cuando en cada vuelta el problema se reduce a la mitad (como en la búsqueda binaria), la cantidad de pasos es log₂(n): de 1.000.000 a 1 hay solo unas 20 divisiones por 2.

int ini = 0, fin = n - 1;
while (ini <= fin) {                 // Se repite log₂(n) veces.
    int medio = (ini + fin) / 2;
    if (arr[medio] == buscado) return medio;
    if (arr[medio] < buscado) ini = medio + 1;   // Descarto la mitad de abajo.
    else fin = medio - 1;                         // Descarto la mitad de arriba.
}   // En cada paso el rango se parte al medio ⇒ O(log n).

Técnica paso a paso para un método entero

Cuando hay if, throw y bucles mezclados, conviene atacar el código por partes y armar la cuenta de a poco:

  • Costo de un if = costo de la condición + el peor de sus ramas: costo(if) = costo(condición) + peor(then, else). No se suman las dos ramas: solo cuenta la más cara, porque en una corrida se ejecuta una sola.
  • Un throw (lanzar una excepción) es O(1): cortar la ejecución cuesta constante, igual que un return.
  • Tachá las constantes y las ramas baratas: las asignaciones sueltas, los return y los throw son O(1) y se borran del conteo final.
  • Al SUMAR partes en secuencia, gana el término dominante: O(n) + O(1) = O(n); O(n²) + O(n) = O(n²).
  • Al ANIDAR, se multiplica. Un bucle O(n) que adentro llama a una operación que ya es O(n), todo dentro de otro bucle O(n), da n × n × n = O(n³).
int buscarPosicion(int[] arr, int x, int n) {
    if (n == 0)                       // condición: O(1)...
        throw new RuntimeException(); // ...rama: throw es O(1).  Todo el if: O(1).
    for (int i = 0; i < n; i++) {     // bucle: O(n)...
        if (arr[i] == x) return i;    // cuerpo: O(1) (comparar + return).
    }
    return -1;                        // O(1), se tacha.
}   // O(1) + O(n) ⇒ gana el dominante ⇒ O(n).
⚠️ El caso engañoso: dos while que comparten la MISMA i Si dos bucles están anidados pero comparten una variable i que no se reinicia, i avanza en total n veces sumando todas las vueltas, no n por cada vuelta del de afuera. Eso es O(n), NO O(n²).
int i = 0;
while (i < n) {              // Parece el bucle externo...
    while (i < n && arr[i] == 0) {   // ...pero usa la MISMA i y NO la reinicia.
        i++;                // i nunca vuelve a 0: avanza en total n veces.
    }
    i++;
}   // Entre los dos while, i pasa una sola vez por cada valor ⇒ O(n), no O(n²).

Distinto es el bucle triangular, donde el interno arranca en i (o va hasta i) y sí se reinicia en cada vuelta del externo: hace n + (n-1) + ... + 1 ≈ n²/2 pasos, que descartando la constante es O(n²).

for (int i = 0; i < n; i++) {       // n veces...
    for (int j = 0; j <= i; j++) {   // ...el interno SÍ se reinicia, llega hasta i.
        comparar(arr[i], arr[j]);    // n + (n-1) + ... + 1 ≈ n²/2 ⇒ O(n²).
    }
}

Costo espacial y recursión

Además del costo temporal (cuántas operaciones), a veces se pide el costo espacial: cuánta memoria extra usa el algoritmo según n. Un algoritmo iterativo que solo usa unas variables sueltas es O(1) espacial, aunque su tiempo sea O(n).

La recursión es donde el costo espacial se vuelve interesante: cada llamada que todavía no terminó queda apilada en la pila de ejecución. Por eso el costo espacial de un algoritmo recursivo es O(profundidad), la cantidad de llamadas anidadas que conviven al mismo tiempo:

  • Factorial o recorrer una lista: una llamada por elemento ⇒ profundidad n ⇒ O(n) espacial. La versión iterativa hace lo mismo con un bucle y unas variables ⇒ O(1) espacial.
  • Recorrer un árbol: se apila una llamada por nivel ⇒ profundidad = altura del árbol ⇒ O(altura) espacial.
  • Si la recursión no llega al caso base (se llama sin achicar el problema), la pila crece sin freno hasta reventar: StackOverflow.
int factorial(int n) {
    if (n <= 1) return 1;            // caso base: corta la recursión.
    return n * factorial(n - 1);     // se apila una llamada por cada n, n-1, ...
}   // Tiempo O(n) y espacio O(n): hay n llamadas apiladas a la vez.
⚠️ Fibonacci recursivo: árbol de llamadas que se duplican fib(n) = fib(n-1) + fib(n-2) abre dos llamadas por cada una, y esas se vuelven a abrir: el árbol de llamadas duplica su ancho a cada nivel ⇒ O(2ⁿ) temporal. Recalcula los mismos valores miles de veces; por eso conviene una versión iterativa (O(n) tiempo, O(1) espacio).

5. Errores comunes

⚠️ Sumar en vez de multiplicar bucles anidados Si un bucle está adentro de otro, los costos se multiplican (n × n = n²), no se suman. La suma (n + n = 2n, que es O(n)) corresponde a dos bucles uno después del otro, no anidados.
⚠️ Confundir mejor caso con peor caso Big-O describe el peor caso. Una búsqueda lineal puede encontrar el valor en el primer intento (mejor caso, O(1)), pero su complejidad es O(n) porque en el peor caso recorre todo.
⚠️ Creer que O(2n) ≠ O(n) Las constantes no cambian el orden: O(2n) = O(n), igual que O(n/2) o O(100n). Lo único que importa es cómo crece, no el factor que lo multiplica.
💡 Tip de parcial Frente a un código: contá los bucles. Anidados ⇒ multiplicá. En secuencia ⇒ quedate con el más costoso. Algo que se divide a la mitad ⇒ log n.

6. Resumen

  • Big-O mide cómo crece el costo según n, en el peor caso.
  • En la cátedra alcanza con clasificar C ≈ O(1), L ≈ O(n), P ≈ O(n²) o más; sin demostraciones formales (sin c ni n₀).
  • Se ignoran constantes y términos menores: 3n + 5 ⇒ O(n).
  • Órdenes de mejor a peor: O(1) → O(log n) → O(n) → O(n log n) → O(n²) → O(2ⁿ).
  • Bucle simple ⇒ O(n); bucles anidados ⇒ se multiplican (O(n²)); dividir a la mitad ⇒ O(log n).
  • Técnica: costo(if) = condición + peor(then, else); throw es O(1); al sumar gana el dominante, al anidar se multiplica. Ojo con la i que no se reinicia (es O(n), no O(n²)) y con el triangular (sí O(n²)).
  • Costo espacial: la recursión apila una llamada por nivel ⇒ O(profundidad) (O(n) en factorial/lista, O(altura) en árboles); la iterativa suele ser O(1). Fibonacci recursivo = árbol duplicado ⇒ O(2ⁿ).
  • Recordá: un for con tope fijo (i < 5) es C / O(1), no lineal; O(2n) = O(n); y Big-O es el peor caso, no el mejor.
