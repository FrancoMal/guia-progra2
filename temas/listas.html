Memoria dinámica y listas enlazadas

1. ¿Qué es y cuándo se usa?

La memoria dinámica es la que pedimos en tiempo de ejecución: cada vez que hacemos new creamos un objeto nuevo y obtenemos una referencia a él. No hace falta saber de antemano cuántos vamos a necesitar; los vamos creando a medida que el programa corre.

Sobre esa idea se construye la lista enlazada: una cadena de nodos donde cada nodo guarda un valor y una referencia al siguiente. El último nodo apunta a null, que marca el final de la lista.

5→ 3→ 8→ null

Se usa cuando el tamaño cambia mucho (insertar y borrar sin reservar de más) y como base para implementar muchos TDAs. De hecho, las implementaciones "LD" (lista dinámica) de Pila, Cola, Conjunto y Diccionario se arman con exactamente esta idea de nodos enlazados.

2. Ideas clave

  • Referencia al primero: la lista "es" su primer nodo. Guardamos una sola variable (por convención del curso, origen) que apunta al primer nodo; desde ahí llegamos a todos los demás siguiendo los sig.
  • El turista: para recorrer la lista no movemos origen (si lo perdemos, perdemos la lista entera). Usamos un nodo auxiliar — el turista — que arranca en origen y va "caminando" con turista = turista.sig hasta llegar a null.
  • Diferencia con un arreglo: el arreglo tiene tamaño fijo y permite acceso directo por índice (datos[i] es O(1)). La lista tiene tamaño dinámico (crece y se achica nodo a nodo) pero solo permite acceso secuencial: para llegar al elemento i hay que recorrer los anteriores.
📌 Convención del curso El nodo es una clase interna class Nodo { int valor; Nodo sig; } y la referencia al primer nodo se suele llamar origen. El nodo que usamos para recorrer es el turista.

3. Operaciones (Java)

Definimos el nodo y la lista. Todas las operaciones trabajan sobre la referencia al primero (origen):

public class ListaLD {
    class Nodo { int valor; Nodo sig; }   // Cada nodo: un valor y una referencia al siguiente.
    Nodo origen;                          // Referencia al primer nodo de la lista.

    // Inicializar: lista vacía = referencia en null.
    public void inicializar() {
        origen = null;
    }

    // Agregar adelante: O(1). El nuevo nodo pasa a ser el primero.
    public void agregarAdelante(int x) {
        Nodo nuevo = new Nodo();
        nuevo.valor = x;
        nuevo.sig = origen;   // El nuevo apunta al viejo primero...
        origen = nuevo;       // ...y pasa a ser el nuevo primero.
    }

    // Recorrer e imprimir con el turista.
    public void imprimir() {
        Nodo turista = origen;                // El turista arranca en el primero.
        while (turista != null) {             // Mientras no llegue al final...
            System.out.println(turista.valor);
            turista = turista.sig;            // ...avanza al siguiente.
        }
    }

    // Buscar un valor: devuelve true si está. O(n).
    public boolean buscar(int x) {
        Nodo turista = origen;
        while (turista != null && turista.valor != x)
            turista = turista.sig;
        return (turista != null);             // Si no es null, lo encontró.
    }

    // Eliminar el nodo que contiene x.
    public void eliminar(int x) {
        if (origen != null) {
            if (origen.valor == x) {
                origen = origen.sig;          // Caso especial: borrar el primero.
            } else {
                Nodo turista = origen;
                // Avanzo hasta el nodo ANTERIOR al que quiero borrar.
                while (turista.sig != null && turista.sig.valor != x)
                    turista = turista.sig;
                if (turista.sig != null)
                    turista.sig = turista.sig.sig;   // Salteo el nodo: lo desengancho.
            }
        }
    }
}
💡 Por qué el turista en eliminar mira sig Para borrar un nodo necesitamos al anterior, porque hay que cambiar su sig para que saltee al borrado. Por eso el while avanza mientras turista.sig.valor != x, no turista.valor.

4. Costo

OperaciónLista enlazada
inicializarO(1)
agregarAdelanteO(1)
imprimir / recorrerO(n)
buscarO(n)
acceder al elemento iO(n)

Insertar adelante es O(1) porque solo enganchamos un nodo, sin recorrer nada. En cambio buscar, recorrer o acceder a una posición son O(n): en el peor caso hay que pasar por todos los nodos. Esa es la contracara del acceso directo O(1) del arreglo.

5. Errores comunes

⚠️ Perder la referencia al primero Si pisás origen mientras recorrés (por ejemplo origen = origen.sig en lugar de mover el turista), perdés el acceso a todos los nodos anteriores: la lista se "pierde".
⚠️ NullPointerException al recorrer Hacer turista.sig o turista.valor sin chequear antes turista != null revienta cuando el turista ya llegó al final. Por eso la condición siempre es while (turista != null && ...) — y en ese orden, para cortar antes de desreferenciar.
⚠️ Olvidar enganchar el sig Al insertar hay que setear nuevo.sig antes de mover origen; al borrar hay que reasignar el sig del anterior. Si olvidás un enganche, partís la lista o dejás nodos colgados.

6. Resumen

  • Memoria dinámica: creamos nodos con new en tiempo de ejecución.
  • Cada nodo guarda un valor y un sig; el último apunta a null.
  • La lista se accede por su primer nodo (origen) y se recorre con un turista auxiliar.
  • Insertar adelante es O(1); buscar, recorrer y acceder son O(n).
  • Es la base de las implementaciones LD de Pila, Cola, Conjunto y Diccionario.
