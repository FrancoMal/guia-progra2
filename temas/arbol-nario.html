Árbol genérico (n-ario)

1. ¿Qué es un árbol n-ario (genérico)?

Hasta ahora vimos el árbol binario, donde cada nodo tiene a lo sumo dos hijos (izquierdo y derecho). Un árbol n-ario —también llamado árbol genérico o simplemente árbol a secas— levanta esa restricción: cada nodo puede tener cualquier cantidad de hijos (cero, uno, dos, cinco, veinte…). No hay un máximo fijo.

Es la estructura jerárquica más general. Aparece todo el tiempo en la vida real:

  • Árbol de directorios: una carpeta puede contener muchas subcarpetas y archivos. La carpeta raíz no tiene un límite de "dos hijos".
  • Organigrama de una empresa: un gerente puede tener a su cargo a varias personas; cada una, a su vez, puede dirigir a otras tantas.
  • El árbol de comentarios de una publicación, el menú de una aplicación, la estructura de un documento HTML (cada etiqueta puede tener N etiquetas hijas)…
raíz: 2→ hijo: 7→ hijo: 21→ hijo: 8

En este ejemplo, la raíz 2 tiene tres hijos (7, 21 y 8): algo imposible en un árbol binario. Toda la terminología que ya conocés —raíz, hoja, nodo interno, padre/hijo, ancestros/descendientes, profundidad, altura, subárbol— vale igual acá; lo único que cambia es que un nodo ya no está limitado a dos hijos.

2. Representación "hijo-mayor / hermano-siguiente"

Acá aparece el truco central de la unidad. Si un nodo puede tener N hijos, lo ingenuo sería que cada nodo guardara una lista de referencias a hijos de tamaño variable. Pero hay una idea más elegante que reutiliza todo lo que ya sabemos de árboles binarios: la representación hijo-mayor / hermano-siguiente (en inglés, left-child right-sibling).

La idea: cada nodo guarda solo 2 referencias, igual que un árbol binario, pero con un significado distinto:

  • HijoMayor: apunta al primer hijo del nodo (el subárbol que está más a la izquierda). Es el "hijo principal".
  • HermanoSiguiente: apunta al próximo hermano, es decir, al siguiente nodo que tiene el mismo padre y está a su derecha.

Con esas dos referencias alcanza para representar cualquier cantidad de hijos: el primer hijo se llega por HijoMayor, y a los demás hijos se llega encadenándolos como hermanos, uno detrás de otro, vía HermanoSiguiente. Así, un árbol n-ario se reduce a un árbol binario: la rama "izquierda" pasa a ser "primer hijo" y la rama "derecha" pasa a ser "hermano siguiente".

Cómo se mapea, paso a paso

Tomemos la raíz 2 con sus tres hijos 7, 21 y 8. En la cabeza lo dibujamos "ancho":

2 ┬→ 7 ├→ 21 └→ 8

Pero internamente, con hijo-mayor / hermano-siguiente, se guarda así: el 2 apunta por HijoMayor solo al primero (7); y 7 apunta por HermanoSiguiente a 21, que a su vez apunta por HermanoSiguiente a 8. Los tres hijos forman una cadena de hermanos:

2⬎ hijoMayor 7→ hermSig 21→ hermSig 8→ null

Leído como árbol binario: la referencia "baja" (hijoMayor) hace de izquierda y la referencia "a la derecha" (hermanoSiguiente) hace de derecha. Por eso el nodo de la implementación se ve idéntico al de un binario, solo cambian los nombres:

class Nodo {
    int valor;          // El dato que guarda el nodo.
    Nodo hijoMayor;     // Primer hijo (más a la izquierda); null si es hoja.
    Nodo hermanoSig;    // Próximo hermano (mismo padre, a la derecha); null si es el último.
}
💡 La clave de la unidad Esta representación es la razón por la que el TDA árbol genérico se estudia justo antes o junto con los binarios: convierte un problema "de N hijos" en uno "de 2 referencias". Si sabés recorrer un binario, sabés recorrer un n-ario; solo cambia qué significan las dos referencias (hijoMayor en vez de izq, hermanoSig en vez de der).

3. Interfaz del TDA Árbol N-ario (ANaTDA)

El apunte define el TDA del árbol genérico solo a nivel de especificación (no se ve una implementación concreta, a diferencia de pila o cola). La interfaz se llama ANaTDA (Árbol N-ario TDA). Sus operaciones:

  • Valor(): recupera el valor de la raíz del árbol.
  • HijoMayor(): devuelve el subárbol del hijo más a la izquierda (otro ANaTDA).
  • HermanoSiguiente(): devuelve el subárbol del hermano siguiente (otro ANaTDA).
  • arbolVacío(): indica con un boolean si el árbol está vacío.
  • inicializarArbol(): inicializa la estructura (deja el árbol vacío).
  • crearArbol(valor): asigna ese valor como raíz del árbol.
  • agregarHijoMayor(valor): agrega el valor dado como raíz del nuevo subárbol hijo (queda como primer hijo).
  • eliminarHijoMayorConDescendientes(): elimina el subárbol del hijo más a la izquierda con todos sus descendientes (poda esa rama entera).
  • eliminarHermanoSiguienteConDescendientes(): elimina el hermano siguiente del árbol dado con todos sus descendientes.

Fijate que, igual que en el BinaryTree recursivo, HijoMayor() y HermanoSiguiente() no devuelven un valor, sino otro árbol (un ANaTDA): el subárbol completo. Para leer el dato del primer hijo harías arbol.HijoMayor().Valor().

public interface ANaTDA {
    int Valor();                                 // Valor de la raíz.
    ANaTDA HijoMayor();                           // Subárbol del primer hijo.
    ANaTDA HermanoSiguiente();                    // Subárbol del hermano siguiente.
    boolean arbolVacío();                         // ¿Está vacío?
    void inicializarArbol();                      // Inicializa (árbol vacío).
    void crearArbol(int valor);                   // Asigna 'valor' como raíz.
    void agregarHijoMayor(int valor);             // Agrega 'valor' como primer hijo.
    void eliminarHijoMayorConDescendientes();     // Poda el primer hijo y su subárbol.
    void eliminarHermanoSiguienteConDescendientes(); // Poda el hermano siguiente y su subárbol.
}

4. Recorridos sobre la representación hijo-mayor / hermano-siguiente

Como cada nodo tiene exactamente dos referencias (hijoMayor y hermanoSig), recorrer un árbol n-ario es recursión doble, muy parecida a la de un árbol binario. En cada nodo:

  • recursás por HijoMayor para bajar a los hijos de ese nodo;
  • recursás por HermanoSiguiente para seguir con los hermanos (los otros hijos del mismo padre).

El caso base es siempre el mismo: un árbol/nodo vacío (null), que corta la recursión.

// Imprime TODOS los valores del árbol n-ario (recorre todo el árbol).
void recorrer(Nodo nodo) {
    if (nodo == null) return;           // Caso base: subárbol vacío.
    System.out.print(nodo.valor + " "); // Proceso este nodo.
    recorrer(nodo.hijoMayor);           // Bajo a sus hijos (empezando por el primero)...
    recorrer(nodo.hermanoSig);          // ...y sigo con sus hermanos (los demás hijos del padre).
}

Una sola llamada a recorrer(raiz) visita el árbol entero: la recursión por hermanoSig barre toda la cadena de hermanos de cada nivel, y la recursión por hijoMayor baja un nivel desde cada nodo.

Contar nodos, contar hojas

El mismo esquema sirve para casi cualquier cálculo. Para contar todos los nodos, sumás 1 (por el nodo actual) más lo que aporten su hijo-mayor y su hermano-siguiente:

// Cantidad total de nodos del árbol.
int contarNodos(Nodo nodo) {
    if (nodo == null) return 0;                 // Vacío: aporta 0.
    return 1                                    // Este nodo cuenta 1...
         + contarNodos(nodo.hijoMayor)          // ...más todos sus descendientes...
         + contarNodos(nodo.hermanoSig);        // ...más todos sus hermanos (y los de ellos).
}

Para contar hojas hay que tener cuidado con qué es una hoja en esta representación: una hoja es un nodo sin hijos, es decir, con hijoMayor == null. ¡Que tenga hermanoSig no importa! Un hermano siguiente no es un hijo, es otro nodo del mismo nivel.

// Cantidad de hojas (nodos sin hijos: hijoMayor == null).
int contarHojas(Nodo nodo) {
    if (nodo == null) return 0;
    int aca = (nodo.hijoMayor == null) ? 1 : 0; // Es hoja si NO tiene hijo mayor.
    return aca
         + contarHojas(nodo.hijoMayor)          // Hojas que cuelgan de sus hijos...
         + contarHojas(nodo.hermanoSig);        // ...y hojas entre sus hermanos.
}
⚠️ El error clásico del n-ario Confundir hijo con hermano. En esta representación, hijoMayor baja un nivel (son los hijos reales) y hermanoSig se queda en el mismo nivel (otros hijos del mismo padre). Un nodo es hoja si hijoMayor == null, sin importar si tiene o no hermanoSig. Tratar el hermano siguiente como si fuera un hijo cuenta mal los niveles, la altura y las hojas.
📕 Versión con el TDA recursivo (ANaTDA) Si en vez del modelo "Nodo con referencias" usás el TDA ANaTDA, la lógica es la misma pero viajan subárboles en la recursión (igual que con BinaryTree): 
void recorrer(ANaTDA arbol) {
    if (arbol == null || arbol.arbolVacío()) return;  // Caso base.
    System.out.print(arbol.Valor() + " ");
    recorrer(arbol.HijoMayor());          // Subárbol del primer hijo.
    recorrer(arbol.HermanoSiguiente());   // Subárbol del hermano siguiente.
}
Cambia quién viaja (un subárbol entero en lugar de una referencia a nodo), pero el patrón "proceso la raíz, recurso por hijo-mayor, recurso por hermano-siguiente" es idéntico.

5. Costo y cuándo usarlo

OperaciónCosto
Valor, HijoMayor, HermanoSiguiente, arbolVacíoO(1)
crearArbol, agregarHijoMayorO(1)
Recorrer / contar nodos / contar hojasO(n)

Acceder a una referencia o leer el valor de la raíz es O(1): son operaciones directas sobre el nodo. Cualquier recorrido que visite todo el árbol es O(n) (con n = cantidad de nodos), porque toca cada nodo exactamente una vez.

Cuándo usarlo: siempre que la jerarquía a representar tenga nodos con una cantidad de hijos variable o desconocida de antemano —directorios, organigramas, menús, árboles de categorías—. Si en cambio cada nodo nunca pasa de dos hijos y querés búsqueda ordenada, lo natural es un árbol binario (o un ABB). La representación hijo-mayor / hermano-siguiente es valiosa además como idea conceptual: muestra que toda esa variedad de árboles "anchos" se puede guardar con la misma estructura de 2 referencias de un binario.

6. Resumen

  • Un árbol n-ario (genérico) permite que cada nodo tenga cualquier cantidad de hijos, no solo dos. Modela directorios, organigramas, menús, etc.
  • La representación hijo-mayor / hermano-siguiente guarda en cada nodo solo 2 referencias: hijoMayor (primer hijo) y hermanoSig (próximo hermano). Así un árbol n-ario se reduce a un binario.
  • El TDA ANaTDA ofrece Valor(), HijoMayor(), HermanoSiguiente(), arbolVacío(), crearArbol, agregarHijoMayor y las eliminaciones con descendientes. Se ve solo como especificación.
  • Los recorridos son recursión doble: por hijoMayor (bajar a los hijos) y por hermanoSig (seguir con los hermanos). Una hoja es un nodo con hijoMayor == null (el hermano siguiente no cuenta como hijo).
  • Accesos O(1); recorrer todo el árbol O(n).
